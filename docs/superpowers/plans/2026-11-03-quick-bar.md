# Quick Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 60 px quick bar on the right of every keypad screen: four buttons that each open a page of an existing profile as a panel over the keys, plus a top slot where Studio suggests a profile learned from the owner's manual switches, with a go-back.

**Architecture:** The firmware narrows the key area to 420 px and draws the bar beside it. A panel is a second page document (`panelDoc`) that the key grid shows instead of the active page, so the active profile, its page and every host command acting on them stay untouched. Studio learns from three keypad events (`EVT:PROFILE`, the new `EVT:SWITCH`, `EVT:KEY`) and the app in front, and pushes `suggest <slot>` to the keypad.

**Tech Stack:** ESP32 Arduino core 3.2.1 via `tools/kp.py` (arduino-cli), LovyanGFX, ArduinoJson 7, NVS (`Preferences`); pytest hardware tests (`tools/tests/test_device.py`); Electron Studio in plain JS, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-03-quick-bar-design.md`

## Global Constraints

- Bar 60 px wide at x 420–480, y 30–320. Key area 420 px wide. `CELL_W` 84, `KEY` 66 unchanged, 15 keys per page (5×3).
- Four bar buttons, in order Media, Explorer, Git, Commands. Each is `{"profile": 1-16, "page": 1-16, "icon": "<key icon name>", "label": "<≤12 chars>"}` or `null` (empty).
- No new action types. The existing ones: `key`, `keycombo`, `text`, `multiline`, `delay`, `media`, `telephony`, `page`, `back`, `profile`, `host`.
- Animations hold `FPS_FLOOR` = 50 fps or better, including with a panel open.
- Bonds, calibration, profiles and NVS settings survive the update. Never format LittleFS or NVS.
- The owner's real password never appears in the repo, defaults, tests or logs. Personal profiles stay in the git-ignored `/profiles/`.
- Commits are local, on `dev/firmware`, with no Co-Authored-By or Claude-Session lines. The project's message style is a short sentence (`3.11.1: the LED stays dark in deep sleep …`).
- Before flashing, confirm the board: `python -m esptool --port <COM> read_mac`. The daily keypad's base MAC is `8c:94:df:4e:58:f8` (BT …58:FA). The work board's is `8c:94:df:4e:bc:f0` (often COM8).
- Studio: no new dependency, no framework.
- Versions: firmware `FW_VERSION` 3.12.0, Studio `package.json` 3.12.0. The unbuilt Studio redesign (`2026-10-21-studio-ease-of-use-design.md`) becomes 3.13.
- In `test_device.py`, `d.events` is a list of `(time, line)` pairs, so filter with `[l for _, l in d.events[since:] if …]`.

## Review Focus

1. **Studio's autosave re-uploads the active profile while a panel is open.** The upload path (`cli.cpp`, the `if (id == currentProfile)` reload) calls `uiSetProfile` then `uiGoPage`. The panel must stay open on its page, and the active page is restored underneath. Test: Task 3, `test_upload_of_active_profile_keeps_the_panel`.
2. **A button points at a page that no longer exists** (the profile was edited down to fewer pages). A tap does nothing, the button is drawn empty, and nothing crashes. Test: Task 3, `test_button_to_a_missing_page_does_nothing`.
3. **A theme change while a panel is open** (Studio's theme chips, `theme <id>`). It wipes the screen, and the panel must still be open and drawn. Test: Task 3, `test_theme_change_keeps_the_panel`.
4. **Rapid focus changes** (alt-tabbing). Studio sends `suggest` only when the best slot changes, never once per focus event. Test: Task 6, `update sends only when the best changes`.
5. **A missing or corrupt `suggest.json`.** Learning starts empty, and Studio boots. Test: Task 6, `load: missing or corrupt file starts empty`.

### Task 6: The learning model

**Files:**
- Create: `studio/services/suggest.js`
- Test: `studio/test/suggest.test.js`

**Interfaces:**
- Produces:

```js
class Suggest {
  constructor({ now = Date.now, halfLifeDays = 7, minWeight = 3, data = {} } = {})
  static load(file, opts)          // a missing or corrupt file gives an empty model
  save(file)                       // JSON of data: { "<app>": { "<slot>": { w, n, t } } }
  focus(app)                       // the app in front (main.js appKey); a change stops counting
  profile(slot)                    // EVT:PROFILE, whoever caused it: stops counting
  manual(slot)                     // EVT:SWITCH: presses on slot now count for the current app
  key()                            // EVT:KEY state "1" on the active profile
  weight(app, slot)                // w · 0.5^((now − t) / halfLife)
  best(activeSlot)                 // the heaviest slot ≥ minWeight for the current app, not activeSlot; else 0
  update(activeSlot)               // best(activeSlot) if it differs from the last value returned, else null
  reset()                          // the link dropped: the next update() returns the best again
  rows()                           // [{ app, slot, weight, presses, last }], heaviest first
  clear(app, slot)
}
module.exports = { Suggest };
```

A press does `w = weight(app, slot) + 1; t = now; n += 1`. Only `manual` starts counting. `profile` arrives before `manual` for the same switch (the firmware's line order), so the order is: `profile` stops counting, then `manual` starts it again.
